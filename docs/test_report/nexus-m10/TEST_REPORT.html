1. 交付摘要

M10 为 Nexus 控制面补齐 append-only（WORM）审计日志与通用查询 API。所有安全敏感动作（登录 / turn 生命周期 / 审批决策 / 中断）落 audit_logs 表；PG trigger prevent_audit_modification 在 BEFORE UPDATE OR DELETE 阶段 RAISE EXCEPTION，DB 层强制不可变；应用层只 INSERT。新增 GET /v1/audit/logs 与 GET /v1/audit/logs/{id}，admin 可跨租户、非 admin 仅本租户。

  • 新 migration 20260906000006_m10_audit.sql：ALTER ADD COLUMN target_type/target_id/trace_id + WORM trigger + 2 索引
  • 新模块 src/audit.rs：audit_log() INSERT-only（best-effort 不阻塞业务）+ AuditLogRow + list_audit_logs/get_audit_log
  • http_server.rs：4 处埋点 + 2 条路由
  • main.rs：标题 "Nexus M10: serve"

不改 codex 内核（全部在 nexus-control crate）。不动 M3 专用 approval_audit（双轨并存）。

6. 关键决策

6.1 适配现有 audit_logs 表（ALTER 而非 CREATE）

发现 audit_logs 表已存在（早期里程碑建，列 actor_user_id(FK users) / resource / detail_json(NOT NULL default '{}')）。CREATE TABLE IF NOT EXISTS 会跳过→列不存在→INSERT 报 42703。修复：migration 改 ALTER TABLE ADD COLUMN IF NOT EXISTS target_type/target_id/trace_id，audit.rs 列名 actor_user_id/detail_json 适配现有表，保留现有数据与 WORM trigger。Surgical：不重建表、不删旧列。

6.2 WORM 用 PG trigger（DB 层强制）

BEFORE UPDATE OR DELETE RAISE EXCEPTION，即使应用 bug 或越权也无法改写历史。应用层 audit_log() 只 INSERT，best-effort（失败→tracing::error，不 propagate，审计永不阻塞 login/turn/approval）。

6.3 NULL-or-equal 单查询全组合

($2::bigint IS NULL OR tenant_id=$2) AND ($3::text IS NULL OR action=$3) 一个 query 覆盖 admin/非 admin × action 过滤 4 组合，避免分支拼接 SQL。admin（*:*）tenant_filter=None 跨租户；非 admin Some(tid) 本租户隔离。

6.4 detail_json NOT NULL 处理

schema 约束 detail_json NOT NULL，audit_log() 内 detail.cloned().unwrap_or_else(|| json!({}))，None→'{}' 不违反约束。
