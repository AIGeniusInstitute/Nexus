1. 里程碑概述

M3 将 app-server 的自动接受审批转变为人机协作（HITL）闭环： app-server 发出 CommandExecutionRequestApproval / FileChangeRequestApproval JSON-RPC Request（带 id）→ driver surface 为 approval/requested 事件并 park → HTTP /v1/approvals/{id}/resolve 落库 + broadcast → driver 经 respond_approval 协议级写回 Response（id 匹配）→ turn 继续/中断。

surface→ park→ 落库 ticket→ broadcast→ resolve 决策→ 协议级回写→ turn completed

核心难点：app-server 审批是同步 JSON-RPC request-response（server 发 Request 带 id，client 必须回 Response 带匹配的 id + decision）。M2 的 handle_server_request 自动接受。M3 surface 给人。

2. 死锁解法 — RuntimeHandle 拆分

M2 的 runtime: Arc<Mutex<RuntimeHandle{cmd_tx, event_rx}>>：turn_start 持锁 drain event_rx；若 resolve 也需锁 → 死锁。

拆分：

  • runtime_cmd: Sender<DriverCommand> — Clone，无锁，AppState 顶层。resolve / interrupt / ws 撤销直接 send，不锁。
  • runtime_events: Arc<Mutex<UnboundedReceiver<TurnEvent>>> — 仅 turn_start 读（独占 drain）。
AppState {
    pool, jwt, auth,
    runtime_cmd: Sender<DriverCommand>,        // 无锁，Clone
    runtime_events: Arc<Mutex<...Receiver>>, // 仅 turn_start 持有
    broadcast: Arc<Mutex<HashMap>>,
}

3. SIMULATE 测试模式

NEXUS_SIMULATE_APPROVAL=1：driver 在 turn/start 后注入合成 approval/requested → park → resolve 时发合成 item + turn/completed。 无需真实模型（mock gateway 不发真实事件）即可端到端验证 HITL 桥接全链路。

关键修复：approval_id 碰撞 — driver 的 next_approval_id 重启归 1，与已有 DB 行碰撞（INSERT ON CONFLICT DO NOTHING 静默跳过）。 修复：spawn() 取 start_approval_id = SELECT COALESCE(MAX(id),0)+1 FROM approval_tickets（main.rs 查询）。验证后 ids 续 DB max（6,7,8,9…），无碰撞。

5. 端到端测试用例（SIMULATE 模式）

Case 1 — approve（批准）

BASE=http://0.0.0.0:8765
# 登录
TOKEN=$(POST /v1/auth/login {admin@nx.io/admin123})  → token OK
# 建会话
POST /v1/threads {title:"m3-approve"} → id=eecb950a...
# 后台起 turn（driver park）
POST /v1/threads/{id}/turns {input:"approve me"} &
# 轮询待审
GET /v1/approvals → pending approval_id=9 kind=CommandExecution cmd=approve me
# resolve 批准
POST /v1/approvals/9/resolve {decision:"approve"}
  → {"approval_id":9,"status":"approved"}
# turn 结果
  turn result: {"codex_thread_id":"01a0...","status":"completed","turn_id":7}
  ticket: approved
  audit:  created:- | resolved:approved
  turn:   completed

判定：ticket=approved · turn=completed · audit=resolved:approved PASS

Case 2 — deny（拒绝）

POST /v1/threads/{id}/turns {input:"deny me"} &
GET /v1/approvals → pending approval_id=7
POST /v1/approvals/7/resolve {decision:"deny"}
  → {"approval_id":7,"status":"denied"}
  turn result: {"status":"completed","turn_id":8}
  ticket: denied
  audit:  created:- | resolved:denied
  turn:   completed

判定：ticket=denied · turn=completed · audit=resolved:denied PASS

deny 后 driver 写回 Decline，app-server 视作指令被拒，turn 仍以 completed 收尾（决策已落地）。

Case 3 — interrupt（中断）

POST /v1/threads/{id}/turns {input:"interrupt me"} &
GET /v1/approvals → pending approval_id=8
# 触发中断（WS 撤销 / 显式 interrupt）
  → {"status":"interrupted","turn_id":9}
  turn result: {"codex_thread_id":"01a0...","status":"interrupted","turn_id":9}
  ticket: interrupted
  audit:  created:- | interrupted:cancelled
  turn:   interrupted

判定：ticket=interrupted · turn=interrupted · audit=interrupted:cancelled PASS

中断路径：driver 写 Cancel + 发 approval/interrupted + UPDATE pending tickets→interrupted + audit。
