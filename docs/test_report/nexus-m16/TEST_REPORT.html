6. 关键决策

6.1 纯增量，不碰核心路径（Simplicity First + 外科手术）

connectors.rs 全新模块 + migration ALTER 加字段 + 9 路由，不重构 turn_start/drain/runtime/gateway。turn_start 的 260 行 drain 循环零触碰。真实 MCP 转发（T7-1 执行面）未交付，invoke stub 记 tool_call_logs 验证调用链路 + 质量分数据源。

6.2 删除约束保留审计 trail

有 tool_call_logs 的连接器拒绝删除（409 in_use），调用历史作为质量分数据源 + 审计证据不可丢。无调用的连接器可删（200）。

6.3 质量分用 PG COUNT FILTER + NULLIF

COUNT(*) FILTER (WHERE success=true) / NULLIF(COUNT(*),0) 单查询算比率，total=0 时 NULLIF→NULL→coalesce 0.0。Rust 侧 quality_formula 单测覆盖 0/0、2/3、3/3、0/5 四例。

6.4 publish/offline 治理权 vs CRUD 本租户

目录 CRUD（create/list/get/update/delete/invoke/calls/quality）本租户即可（贡献者提交 draft）；上下线治理（publish/offline）需 admin（*:*）——社区贡献→admin 审批发布的治理语义。状态流转单向（draft→published→offline），invalid transition→400。

6.5 选型理由：T12-2 而非 T11-4 协作编排

审查阶段评估两维度：T11-4 多 Agent 协作编排需 drain 逻辑抽取（触碰核心 260 行）+ 编排状态机 + DriverCommand 扩展 + 验证依赖真实/模拟多 turn 链，风险中、自主验证成本高，留 M17。T12-2 零重构、零外部依赖、schema 已铺路（connectors/mcp_servers/tool_call_logs 表已存在）、高可验证，风险低，作为 M16 自主完成。
