6. 关键决策

6.1 trace_id 仅 http_server 层（不经 driver/runtime）

trace_id 在 turn_start INSERT 时由 PG default 生成，http_server 读取后传给 audit 埋点。不经 DriverCommand/TurnEvent/stdio_client——Simplicity First：M10 audit 埋点已在 http_server，trace_id 在此层贯穿即可，避免改 runtime/stdio_client 的大面积涟漪。

6.2 timeline Rust 合并 3 query（非 SQL UNION）

turns/items/approval_tickets 行异构（content_ref vs command vs status），SQL UNION 需统一 cast 到 text，脆且丢类型。Rust 端 3 个 query_as 各自强类型 + sort_by(ts) 合并，清晰且类型安全。

6.3 timeline 不含 audit_logs

职责分离：timeline 是结构回放（turn/item/approval 发生了什么），trace 是审计关联（谁/为什么决策）。audit 有 M10 独立查询 API + M11 trace API，不强塞进 timeline。

6.4 audit_logs.trace_id 是 TEXT（bind 字符串）

M10 建 audit_logs.trace_id 为 TEXT 存 UUID 字符串。trace_lookup 的 audit query bind trace_id.to_string()（非 Uuid），避免 PG UUID vs text 类型不匹配；turn query bind Uuid（turns.trace_id 是 UUID）。

6.5 坑：input_tokens INT4 非 INT8

trace_lookup turn query 初版声明 Option<i64> → ColumnDecode "i64 (INT8) not compatible with INT4"。turns.input_tokens 是 integer（INT4 NOT NULL default 0），改 i32。
