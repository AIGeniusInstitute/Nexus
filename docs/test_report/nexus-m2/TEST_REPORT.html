1. 执行摘要

M2（执行闭环）7 任务全量交付。10 个测试用例全部 PASS。核心闭环打通：用户提交 turn → RuntimeDriver 驱动真实 Codex app-server 执行 → item 事件流落 Postgres（items + app_server_events）→ WS broadcast 实时推送 → turn/completed 收尾。kill app-server 后新 turn 自动 respawn + thread/resume，codex_thread_id 保持稳定，items 历史无缺口连续。

关键突破：M1 的 mock turn_start 替换为真实 app-server 驱动。同步阻塞 stdio 经"专用驱动线程 + tokio channel 桥"接入 async axum，不阻塞 runtime。partial unique index 的 ON CONFLICT 需带 WHERE 谓词（修复了 items 落库静默失败）。interrupt = kill + respawn + resume（M0 验证路径）。

7. 执行闭环数据流

M2 执行闭环：async handler → cmd channel → 驱动线程（阻塞 stdio）→ app-server → 事件回流 → PG 落库 + WS broadcast。kill app-server → 驱动线程检测 is_alive=false → respawn + thread/resume。

8. 关键决策与简化

  • 单驱动线程串行：app-server stdio 天然串行；阻塞 I/O 全在驱动线程，async 不阻塞。M5+ 换 K8s 池。
  • kill+respawn+resume 实现 interrupt/resume：复用 M0 验证路径，不引入 stdin/stdout 并发 select。codex_thread_id 落库 + codex 持久化 thread 状态到 CODEX_HOME → 新进程可 resume。
  • 死进程检测：RunTurn 前查 is_alive()（child.try_wait），死了就 respawn+resume（非 thread/start，保 codex_thread_id）。
  • partial unique index ON CONFLICT 带 WHERE：ON CONFLICT (codex_item_id) WHERE codex_item_id IS NOT NULL——partial index 必须带谓词，否则 PG 报"no matching constraint"，items 落库静默失败（已修复）。
  • items ON CONFLICT DO UPDATE：item/started + item/completed 同 codex_item_id，completed 覆盖 started 的 content_ref。
  • gateway mock/passthrough 双模：env 切换，闭环不依赖 API key。真实模型才触发 tokenUsage/updated。
  • SandboxPolicy::ReadOnly{network_access:true}：允许 app-server 访问 localhost gateway（gateway 是唯一配置的模型端点=受控出口）。沙箱加固 M5+。
