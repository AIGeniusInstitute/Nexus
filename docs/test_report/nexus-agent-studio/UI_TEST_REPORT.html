3. 发现的 Bug + 修复（issue 修复流程）

issue 文档：docs/issues/2026-09-07-agent-studio-thread-row-fk.md

Bug-1：ThreadRow 缺 agent_def_id（功能 bug）

现象：Studio 会话列表「Agent」列对所有会话显示「默认」，即使创建时绑定了 Agent。TC6 首轮失败（list API 响应 agent_def_id=undefined）。

根因：http_server.rs 的 ThreadRow 结构体（M1 时代）未声明 agent_def_id 字段，threads_list SELECT 也未查该列。Agent Studio 加了 threads.agent_def_id 列但未同步 list API。

修复（Surgical，2 行）：

struct ThreadRow {
    id: Uuid, title: Option<String>, status: String, created_at: DateTime<Utc>,
    agent_def_id: Option<i64>,   // ← 新增
}
// SELECT id, title, status, created_at, agent_def_id FROM threads ...  ← 加列

复测：TC6 PASS，agent_def_id=10 expected=10。前端 Studio 列表 Agent 列正确显示绑定 Pill。

Bug-2：delete_agent FK 违约（功能 bug）

现象：删除一个已绑定会话的 Agent 时，DELETE 返回 500（外键违约），Agent 仍在列表。TC14 失败。

根因：agent_defs.rs delete_agent 直接 DELETE FROM agent_definitions，但 threads.agent_def_id 外键为 REFERENCES agent_definitions(id)（默认 ON DELETE NO ACTION），有引用时 PG 拒绝删除。

修复（Simplicity First，app 层事务，不改 schema FK）：

let mut tx = pool.begin().await?;
// 先解绑引用此 Agent 的 threads（SET NULL，thread 继续用默认 prompt）
sqlx::query("UPDATE threads SET agent_def_id=NULL WHERE agent_def_id=$1")...;
sqlx::query("DELETE FROM agent_definitions WHERE id=$1 AND tenant_id=$2")...;
tx.commit().await?;

复测：TC14 PASS，删除前=3 删除后=2（减 1），且绑定的 thread 不被破坏（agent_def_id 置 NULL）。
