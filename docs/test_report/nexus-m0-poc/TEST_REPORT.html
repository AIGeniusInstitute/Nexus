§1 三大假设验证

H1 ✅ 验证通过

app-server 长会话可跨进程恢复

spawn codex app-server → thread/start → turn/start（ls 任务，130 events）→ kill 进程 → respawn → thread/resume(同 thread_id) → turn2（24 events，seq 107-130）。phase1 max_seq=106 kill 前后不变，无丢失无重复。

H2 ✅ 验证通过

execpolicy 规则可下发并生效

生成 Starlark .rules（prefix_rule(["rm"], forbidden) / prefix_rule(["ls"], allow)），写入 <CODEX_HOME>/rules/default.rules，app-server 启动自动加载。4 单测验证 PolicyEvaluator：rm→Forbidden、ls→Allow、justification 可见、未匹配回落。

H3 ✅ 验证通过

三层沙箱（容器+OS+网络）生效

Docker 容器：非 root（uid 1000）+ 只读 rootfs + seccomp（禁 50+ 逃逸 syscall，unshare 被拒）+ cap-drop ALL + --network none/internal + cgroup（CPU/MEM/PID 限额）。5 项自检全过 exit 0；破坏一项（去 --memory）→ exit 1 拒绝调度。

§6 已知限制与后续

AC5.2 gateway 容器化联调（留 M2）：当前 Model Gateway 在宿主进程内验证（单测+PoC），沙箱容器到 gateway 的白名单放行未端到端联调。M2 容器化 gateway + iptables egress 规则后完成 AC5.2 全量。
全集成串联跑真实 ls（留 M2）：sandbox ReadOnly{network_access:false} 阻断模型 API 网络（T0-4/T0-7 的 turn 因此 Failed），PoC 用 DangerFullAccess 验证骨架端到端。M2 经 gateway 代理出站解决。
事件存储 file-backed（留 M1）：PoC 用 file-backed JSON store（HashSet 幂等），非 SQLite/Postgres。M1 迁 PostgreSQL + INSERT ON CONFLICT DO NOTHING + RLS 多租户。
M1 路线：Postgres+RLS 多租户 → 结构化 tracing → thread 所有权 → Fork/Rollback 原语 → 真实模型 API 经 gateway 转发。详见 docs/architecture/09-roadmap/roadmap.md 阶段②。
