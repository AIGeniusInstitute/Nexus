1. 交付摘要

将 Nexus 控制面（M0–M14 全部 15 里程碑产物）标准化为可一键拉起的 Docker 部署包。

  • deploy/Dockerfile：瘦运行时镜像（debian:bookworm-slim + nexus-control + codex 两二进制 + ca-certificates/curl/libsqlite3-0/libssl3）
  • deploy/docker-compose.yml：postgres(pgvector/pgvector:pg16) + nexus 两服务，volume 持久化，健康检查
  • deploy/deploy.sh：一键脚本（编译→打包→启动→健康检查→汇报），含 --down/--purge/--no-build
  • deploy/.env.example + deploy/README.md：环境变量模板与文档

不改 codex 内核（全部在 deploy/ 目录）。镜像 759MB（codex 引擎 strip 后占主体）。

5. 关键决策

5.1 宿主机编译 + 瘦镜像（非容器内全量 cargo build）

codex 工作区 100+ crate，容器内从零 release 编译 30+ min 且需下载 git 依赖；nexus-control 是小 crate，宿主机 24 核 2m54s 完成；codex 引擎复用驱动 M0–M14 的同一二进制（strip 297MB）。瘦镜像构建秒级，image 759MB。

5.2 pgvector/pgvector:pg16（非 postgres:16-alpine）

M13 知识库 RAG 需 pgvector 扩展（vector 类型 + HNSW 索引）。postgres:16-alpine 无 pgvector，必须用 pgvector/pgvector:pg16 镜像。

5.3 迁移自动执行（serve 启动即 run_migrations）

nexus-control serve 启动时调 db::run_migrations（幂等，M1–M14 全部 migration）+ seed_admin。无需独立 migrate 步骤，compose depends_on postgres healthy 即保证顺序。

5.4 PG 主机端口 5435（非 5434）

开发期 nexus-pg-m4 容器已占 5434。compose 内部网络 nexus→postgres:5432 不经主机端口；主机 5435 映射仅供外部 inspect，避冲突且不动开发容器。

5.5 密钥隔离（红线）

NEXUS_MODEL_KEY 仅经 .env → compose environment 注入容器 env，不在镜像层（Dockerfile 无 COPY .env）、不在脚本硬编码、不入记忆。NEXUS_JWT_SECRET 空或默认值时脚本 openssl rand -hex 32 自动生成写入 .env。
