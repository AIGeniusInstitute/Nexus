## 0. 概览

本 RoadMap 将"基于 Codex Harness 构建企业级 Agent-Native 操作系统 Nexus"这一目标，分解为 **5 个阶段、13 个里程碑（M0–M12+）、70 项可执行任务**，每项任务标注所属层、依赖、优先级、复用类型、验收标准与工时估算。

**核心约束**（继承战略路线图）：

| 约束                           | 含义                                                                |
| ------------------------------ | ------------------------------------------------------------------- |
| 不改 Harness 内核              | 上游日均 10+ commit；企业特性经配置驱动 + 事件桥接 + 外壳包装实现   |
| 主集成面 = app-server JSON-RPC | 唯一支持长会话/事件流/中断/审批回写/resume                          |
| 控制平面/执行平面物理分离      | 控制面长期有状态多租户 ↔ 执行面一次性可销毁，仅经协议+对象存储通信 |
| 会话真相在云端                 | 事件即真相，`thread_id+turn_id+item_seq` 幂等键，Pod 死不丢会话   |
| 默认最小权限                   | 新租户默认只读沙箱+全量审批，权限只能显式提升                       |

**总周期**：约 13 个月（M0 PoC 4 周 + M1–M12 各约 1 个月 + M12+ 生态持续）

**人力基线**：建议 8–12 人核心团队（架构师 1、Rust 工程师 2、后端 3、前端 2、DevOps/SRE 1、安全 1、QA 1），PoC 阶段可 4 人精简。

## 4. 关键路径

关键路径 = 决定 MVP 最早完工时间的最长依赖链（见 `roadmap-critical-path.svg`）：

```
T0-1 app-server集成 → T0-2 事件落库 → T0-3 resume验证 → T0-5 三层沙箱
→ T1-1 身份租户 → T1-7 Postgres → T2-1 Runtime池 → T2-3 任务编排Temporal
→ T2-4 会话事件落库 → T4-6 MVP验收
```

**关键路径长度** ≈ PoC(4周) + M1(身份/库) + M2(执行闭环) = MVP 最早完工下限。

**可并行支线**（不阻塞关键路径）：

- 审批 HITL（M3，T3-1~T3-5）可与 M2 后期并行
- 策略中心（M3，T3-3）可与审批并行
- IM Bot / Web 抽屉（M3，T3-4/T3-5）可与审批核心并行
- 配额计费（M4，T4-1）可与 M3 并行启动
