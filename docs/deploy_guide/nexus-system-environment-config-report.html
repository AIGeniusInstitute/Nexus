一句话架构判断： Codex Harness 给的是「一台单用户、本地、可打断的 Agent 引擎」；Nexus 要建的是「让这台引擎变成多租户、可计量、可审计、崩溃不丢会话的企业服务」。前者是执行内核（L5），后者是控制平面（L1–L4 + L6–L7），两者严格分离、不改内核。

2. 系统架构

2.1 八层分层模型

层职责关键模块复用 Codex
L1 接入层多渠道统一入口Web 门户、IM Bot、IDE 插件、OpenAPI、CLI否
L2 网关层南北流量、鉴权、实时推送API Gateway、WS 网关、OIDC/SAML、限流否
L3 控制平面平台大脑与账本身份租户、编排、审批、策略、计量、连接器、知识库否（自建核心）
L4 执行平面Harness 托管外壳Runtime 池、沙箱 Pod、MCP Gateway、Workspace薄壳 + 复用
L5 HarnessAgent 执行内核Agent Loop、Tool Router、ExecPolicy、OS 沙箱是（黑盒不改）
L6 模型层模型访问与计量Model Gateway、多模型路由、Token 计量部分
L7 存储治理持久化与可观测Postgres(RLS)、对象存储、pgvector、WORM 审计、OTel、评测否
贯穿安全合规租户四重取证、KMS、网络策略、审计留存否

2.2 六条设计原则

  1. 控制/执行分离：控制面长期有状态、多租户、强一致；执行面无状态、一次性、可销毁；仅经 app-server 协议与对象存储通信。
  2. Harness 不持有企业真相：租户/权限/凭据/计费/审计全在控制面；沙箱仅持有"本次任务短期令牌 + 最小工作集"。
  3. 事件即事实：所有用户可见状态来自 app-server 事件流；前端不直连 Harness。
  4. 默认最小权限：新租户默认只读沙箱 + 全量审批；权限只能显式提升。
  5. 可重建优于高可用：不为沙箱 Pod 做 HA，而是"任何 Pod 死亡都能从云端状态重建"。
  6. 配置即政策：租户差异表达为下发的 config.toml + execpolicy 规则集，而非代码分支。

3.2 codex 执行引擎（L5，黑盒）

位于 codex-rs/（106+ crate Rust 工作区，Apache-2.0，Tokio async）。一个 Turn 跑七阶段：准入 → 快照 → 采样 → 工具派发 → 结果回写 → 压缩决策 → 完成/中断。核心原语必须区分：

原语层级含义
Thread协议层app-server 长生命周期会话（fork/resume/rollback）
SessionCore 内部运行态持有者，不外暴露
Turn—一次任务往返（用户消息 → 模型推理 → 工具调用 → 结果）
Step—Turn 内一次采样快照
Item—Turn 中可持久化的原子事实（命令、文件编辑、工具结果）
集成红线：必须经 app-server（JSON-RPC）集成，禁用 codex exec（一次性）与 in-process SDK（无法 kill/resume）。只有 app-server 提供 Thread、双向事件流、turn/interrupt、协议级审批回写、thread/resume。

4.2 config.toml + execpolicy（租户下发）

每个租户的 config.toml + .rules 由控制面动态生成写入 NEXUS_CODEX_HOME/rules/tenant-{id}.rules 与 config.toml，app-server 自动加载。差异表达为下发配置而非代码分支。

config.toml 关键字段
[model]
model = "deepseek-v4-pro"      # NEXUS_MODEL 注入
wire_api = "responses"         # codex 强制（chat wire_api 已删）

[approval]
approval_policy = "untrusted" # 非 allow 命令触发真实审批
sandbox_mode = "danger-full-access" # 让 codex 发 CommandExecutionRequestApproval
execpolicy .rules（Starlark 语法）
# prefix_rule: argv 前缀匹配 → 决策
prefix_rule(pattern=["rm","-rf"], decision="forbidden")   # 种子 deny
prefix_rule(pattern=["ls"],        decision="allow")      # 种子 allow
prefix_rule(pattern=["npm","install"], decision="forbidden") # learned (M6)
prefix_rule(pattern=["git","clone"],   decision="allow")     # amendment (M7)

安全单调：deny 永不回退；amendment 优先级 40 < seed deny 80/100；risk=high 拒绝自动 allow。

logs [nexus|postgres]跟随日志

shell进入 nexus 容器 bash
backup [file]pg_dump 逻辑备份到 downloads/（gzip）

8. 安全与合规

🔒 密钥隔离

  • NEXUS_MODEL_KEY 仅经 .env 注入 compose env，不写入镜像/脚本/记忆
  • JWT HS256 随机密钥（openssl rand -hex 32），生产强制非默认
  • 管理员密码 bcrypt 哈希，仅 CLI flag 注入
  • 沙箱内零长期密钥：短期、按任务绑定、可撤销令牌

📜 WORM 审计

  • audit_logs 表 PG trigger prevent_audit_modification：BEFORE UPDATE OR DELETE → RAISE EXCEPTION
  • 应用层 audit_log() 只 INSERT、best-effort（失败不阻塞业务）
  • login / turn / approval / interrupt 全埋点，trace_id 贯穿
  • admin 跨租户可见，非 admin 本租户隔离

🛡️ 沙箱三层隔离

  • 容器层：K8s + Seccomp/AppArmor/Kata/Firecracker
  • 命令层：codex OS 沙箱（Seatbelt/Landlock+seccomp+bwrap）
  • 网络层：NetworkPolicy 默认全禁，仅放行 Model/MCP Gateway

🏢 多租户隔离

  • 逻辑：PG RLS（行级安全）
  • 运行时：namespace 隔离
  • 密钥：按租户 CMK
  • 存储：按租户前缀
  • 四重取证，"租户 A 拿到租户 B 数据"可验证
策略安全单调性： deny 永不回退（人 approve 也不降级 learned deny）。execpolicy amendment 优先级 40 < seed deny；risk=high 拒绝自动 allow；UPSERT WHERE source!='seed' 不覆盖种子 deny。新租户默认只读沙箱 + 全量审批，权限只能显式提升。
